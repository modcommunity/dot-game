# QA tools shared by every game

Five tools that every game wants and that were one game's copy until 2026-10-25. Each is a script in `tools/` that a game's own `tools/<name>.sh` reaches with `cd "$(dirname "$0")/.." && exec ../dot-game/tools/<name>.sh "$@"`, and the game-specific part is a small file. Nothing here is delivered in a pack, so none of it bumps the API level.

## Perf budget: `tools/perf_budget.sh`

Plays each case RUNS times on the GPU box, takes the median of every metric and compares it with `tests/perf_budget.json` (baseline times `1 + tolerance`, past the metric's slack, or past its cap). A baseline taken on another GPU is refused (exit 3), so pin the box with `GPU_BOX` in the game's `perf_run_case`. Exit 0 pass, 1 regression, 2 a run failed, 3 GPU mismatch. `--update` rebases, `--post` sends the result to the nightly panel's /qa (kind perf) through dev01, `--from-runs DIR` re-evaluates saved runs.

The game's `tools/qa.conf` sets `PERF_CASES`, `perf_run_case CASE SECONDS` (prints one `PERF {json}` line with `p50_ms`, `p95_ms`, `p99_ms`, `stall_ms`, `load_s`, `rss_mb`, `gpu`, `resolution` and whatever else it wants to budget), `PERF_METRICS` (`name:slack:cap` words), and optionally `PERF_PACK_DIRS` (summed into `pack_mb`), `PERF_SECONDS` and `perf_prepare`.

## Visual regression: `tools/visual_check.sh` and `visual_compare.py`

Renders each case's shots and compares them with `tests/golden/<case>_<shot>.png`; a failure leaves golden, frame and amplified diff in `.godot/test-logs/visual/`. `--update` re-records, `--post` sends the result and the diffs to /qa (kind visual). `qa.conf` sets `VISUAL_CASES`, `VISUAL_SHOTS` (default `overview eye roof`) and `visual_render CASE`, which must leave `screenshots/<case>_<shot>.png`. Re-record only on the same kind of GPU the goldens came from.

## Netchaos: `tools/netchaos.sh`, `netchaos_tc.sh`, `netchaos_eval.py`

A real dedicated server on this machine and two remote clients plus one local, with only the game's UDP port impaired by `tc netem` (clean, lossy100, jitter200, awful400, bwcap, blackout; limits per profile in `netchaos_eval.py`). The game supplies `tools/netchaos_server.tscn` and `tools/netchaos_client.tscn` whose scripts extend `DotGameNetchaosServer` and `DotGameNetchaosClient` (`addons/dot_game/qa/`) and override a handful of hooks: `_configure`, `_prepare`, `_boot_world`, `_players`, `_net_alive` on the server; `client_scene`, `fire_action`, `_roster` on the client (the roster watch finds the game node by its `game` property, any variable with `players()`, or group `game`; test `examples/headless_netchaos_roster.tscn`). `NC_SOLID=1` keeps `mp_solidplayers` on. Each direction has its own netem (dport matches to band 3, sport to band 2), so with `--remote 0`, where both directions cross `lo`, bwcap is still 256 kbit each way; one shared queue halved it and tail-dropped inputs behind snapshots, which read as 3.5 m wall mispredictions. In blackout the first snapshot after the dark seconds corrects by up to speed times their length (the server ran them on neutral input): the eval reports that resume correction per client and judges the worst-correction limit on the rest (`RESUME_S`, `NC_BLACKOUT_AT`/`NC_BLACKOUT_S` from `netchaos.sh`). When the predictor matches nearly every snapshot (`skip_matching_replays`) a run has only a handful of replays, and corrections / replays (13 of 17 on 2-9 cm errors) is noise: under `SPARSE_REPLAYS` (50) replays the eval judges corrections against all reconciles (replays plus the `predictor.skipped` the client report now carries) at a tenth of the rate limit. The report also lists `small_corrections` (2 cm up to the spike size, with the pilot state) and `predictor` (skipped, mismatches, unpredicted). A game whose pilot can be killed by the server (buses) should make the pilot invulnerable in its `netchaos_server.gd`: a round that restarts at once teleports the dead pilot, and the client sees that as a 50 m correction. Never edit the rig's scripts or the `.gd` files while a run is in progress (bash reads a script as it runs, and a run that dies leaves netem armed: `netchaos_tc.sh clear <dev>` on each box).

## Client prediction bench: `DotGameClientBench`

`addons/dot_game/qa/dot_game_client_bench.gd`: the real client scene in one process, the game's dedicated server in a second, dot-net's latency relay between them, and a printout of replays, skipped reconciles, mismatches by variable (`--mismatches`), replayed ticks, fps and the clock. It found arena's float32 rewind bug, which made browser clients replay on nearly every snapshot. A game adds `tools/client_bench.tscn` (one Node) with a script extending the class and overriding `_configure` (`client_scene`, the pilot's actions), `_prepare` (scratch settings) and `_boot_server` (build the server under the node, add the bots, return its `DotNetManager`; `make_server_config` helps). Run `heavy -- timeout 600 godot --headless --path . res://tools/client_bench.tscn -- --play --bots 8 --delay 40 --burn 14 --seconds 20 --mismatches`; `--timeline` (a line every 2 s), `--raw-input` (predict on the sampled command), `--jitter`, `--tick` too; `--delay` is milliseconds each way, `--burn MS` spends MS of wall time in every frame before the client runs (a slow device). The server is the same scene with `--role server`, killed at the end. game-playlot's `tools/client_bench.gd` is the smallest example.

## Solo-client perf bench: `DotGamePerfBench`

A game's real client offline on a fixed map, mode, bot count and seed, recorded by the client's own dot-profiler: the same per-system table as a player's `profiler_record`, plus a sidecar of engine numbers (draw calls, objects, physics, tick rate, renderer, adapter). A game's `tools/perf_bench.gd` extends `DotGamePerfBench` (`addons/dot_game/qa/dot_game_perf_bench.gd`), sets `client_scene` in `_configure` and overrides the hooks it needs (`_select`, `_start_pilot`, `_add_counters`, `_record_begin/_end`, `_sidecar_extra`); `tools/perf_bench.tscn` holds the script, and `tools/perf_bench.sh` execs `addons/dot_game/tools/dot_game_perf_bench.sh` (set `PERF_BENCH_REF` first for the game's reference profile). Run it windowed on a GPU box (`tools/perf_bench.sh --box staging02`), never headless: headless has no renderer, so the render cost reads as zero. `--ab DIR_A DIR_B -n 3` runs A,B,A,B on one pinned box and prints per-system mean deltas; `dot_game_perf_bench_compare.py` diffs a run against a reference profile. Users: arena (pilot, motor timers) and zombie-zone (plain).

The sidecar also holds the bench's own clock, which does not depend on the profiler: `frame_ms` (`avg`, `p50`, `p95`, `p99`, `max`, `fps`), `wall_s`, `ticks`, and `dropped_ticks` / `dropped_per_sec` (ticks real time asked for and the engine's step cap dropped, so a game running slower than the clock shows here and not only as a lower frame rate). `--profiler record|idle|off` says what the profiler does during the measured span (`record` is the default; `idle` places it without a recording; `off` never places it), so `tools/perf_bench.sh --box staging02 --ab "$PWD::--profiler off" "$PWD::--profiler record" -n 3` prices the profiler itself: read the `bench clock` rows, which compare the same clock on both sides. `dot_game_perf_bench_compare.py --per-tick RUN...` prints the per-tick systems in ms per game tick. **Inert-world guard:** the sidecar counts `nodes_added` / `nodes_added_per_tick` (nodes entering the tree in the window; a live 32-player match makes 0.4-1.3 a tick, a dead one ~0.001). Below `PERF_BENCH_INERT_PER_TICK` (0.05) the wrapper prints `WARN INERT RUN`, the summary prints `INVALID` and exits 3, and `--ab` refuses to rank A against B (a match that never started once read as a 20% speedup). `dot_game_perf_bench_compare.py --check LOG...` runs only that test; older logs fall back to the profiler's `engine.nodes_added`.

**First-use hitch:** `--first-use 1` calls the game's `_first_use(game)` hook after `_select` and before the pilot. The hook calls `time_first_use(name, action, after, after_at, frames)` once per thing it wants priced (equip a weapon, fire it, fire it again). Each call takes the median of a baseline of frames, runs the action, and records the worst frame after it (`worst_ms`, `over_ms` above the baseline, its frame index `at`) together with the pipeline compiles in that window (`pipeline_compiles()`, the engine's mesh, surface, draw and specialization compile counters). The rows go into the sidecar's `first_use` list. `--check` and `--ab` print them per name (mean worst ms, the per-run values, mean compiles), and `--ab` prints them even for an inert `--bots 0` run, because bots make the frame too noisy to blame one shot. A cold first use reads as compiles above 0 and a worst frame well above the second use. Arena prices its weapon prewarm with `tools/perf_bench.sh --box staging02 --ab "$PWD" "$PWD::--prewarm 0" -n 3 -- --first-use 1 --bots 0`.

## Phone frame: `addons/dot_game/tools/dot_game_phone_shot.sh`

One 844x390 frame of the game's real offline client with touch forced on (`DotPlatform.touch_override`), so the HUD, the touch Menu button and the touch buttons are all built and the overlap between them can be looked at. The script instances a scene (default: the project's main scene; `--scene=`), sets `force_offline`, waits for the root's `player` (`--ready=`), settles `--frames` frames and writes `screenshots/phone.png` (`--out=`). `--set=prop=value`, `--call=[NodePath:]method[:arg1,arg2]` (repeatable; arguments are Godot literals or strings), `--size=WxH` (default 844x390; 667x375 and 932x430 are the other phone sizes), `--no-touch`. A game's `tools/phone_shot.sh` is one line: `exec bash "$(dirname "$0")/../addons/dot_game/tools/dot_game_phone_shot.sh" "$@"`. It needs xvfb (`--headless` renders nothing), so run it through `heavy`. It refuses to write a frame that is one flat colour.

`MOVIE=1` runs it under `--write-movie`, as the filmstrip tools do; a settled frame comes out the same as without it. A grey frame is a capture taken before the client has drawn (a 2D client that builds over several frames, or a `--headless` run, whose renderer is null), so the tool waits for the ready property, settles N frames and refuses a flat single-colour image (exit 4) instead of writing it. A 3D map in Forward+ on llvmpipe can pass the heavy memory cap and be OOM-killed with no message: set `RENDERER=gl_compatibility`.

## Which suites a change needs: `dot-ci/scripts/affected.sh`

See dot-ci. It is the other half: what to run after an edit to an addon.

Netchaos runs on dev01's nightly: `Netchaos arena` and `Netchaos ZZ` nightly with the default profiles, and `Netchaos full weekly` (Sundays 02:00) with all six. The jobs are rows in the nightly database, documented in `~/stack/nightly/README.md`; each ends in `tools/netchaos.sh --post`.

A `godot --script` tool that writes project files (`dot_game_cfg_templates.gd`, any generator) is run as `GPU_OFFLOAD=0 heavy -- ...`: `heavy` may offload it to a staging box, which writes its own copy of the files, not yours.

## Cover server

`tools/cover_server.tscn` is the headless dedicated server `tools/render_cover.gd` joins. The game's `tools/cover_server.gd` extends `DotCoverServer` (`addons/dot_game/qa/`, tool-only, no API level) and overrides `_default_port`, `_max_players`, `_hostname` and `_boot`; a game that boots through a descriptor and module calls `boot_descriptor_module(path)` from `_boot`. Suite: `examples/headless_cover_server.tscn`.

## Load and audio probes

`DotLoadProbe` and `DotAudioProbe` (`addons/dot_game/qa/`, tool-only, no API level) are the loops ten and five games each copied; a game's `tools/load_probe.gd` / `tools/audio_probe.gd` extends one and overrides the hooks, with a one-script `.tscn` beside it. Run under `xvfb-run -a godot --path . res://tools/load_probe.tscn -- [--frames=90] [--shot=N]` (never `--headless`: no render, and the audio driver is Dummy).

- `DotLoadProbe`: `_make_client` (required), `_default_frames`, `_gate`, `_covered`, `_body`, `_columns` (the text between `covered=` and `pos=`), `_line`, `_shot_wanted`, `_shot_path`, `_started`, `_done`, `_finish`, `report`.
- `DotAudioProbe`: `_make_audio` and `_cue_ids` (required), `_min_length`, `_cue_position`, `_after_cues(sink)` (the game's own checks, awaited, return false to fail), `report`, `_finish`. dot-audio is duck-typed: the audio node needs `setup()` returning something with `ok` and a `manager` whose `sink` has a `bank`.

Not covered: g2gfast's `load_probe` (a server-tick cost bench, nothing to do with the client), and the audio probes that drive a real client (look-at-me, dangerous-delivery, playlot, smash-copter, arena, g2gfast). Suite: `examples/headless_probes.tscn`.


## Sharded suites

`DotGameShardArgs` (`addons/dot_game/qa/`, tool-only) is what a sharded suite reads from its command line: `shard()` (`-- --shard NAME`, "" for the whole suite), `is_merge()` / `merge_logs()` (`-- --merge LOG...`), `slice(items, shard, count)` (round-robin `m0`..`mN-1`), `missing(logs)` and `sections_entered(logs)` for the merge check. `game.sh test NAME.SHARD` / `NAME.merge` (dot-game-template `suite_shards`) pass the arguments. Users: arena, zombie-zone, prop-hunt. Suite: `examples/headless_shard_args.tscn`.
